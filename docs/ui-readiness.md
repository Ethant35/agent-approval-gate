# Dashboard readiness

Author: Ethan

The dashboard is a local operator console for the same authenticated gateway used by the CLI. It is not a hosted service. Start the gateway in a trusted terminal, then open `http://127.0.0.1:3741`. The first-use guide explains how to find the private `human.token`; it can be skipped and replayed later. The guide does not create a sample request or change policy.

The human token stays in the current browser tab's session storage and is cleared on Disconnect. The setup choice, theme, and dashboard filters are preferences, not credentials. Read the action's full parameters before approving it. Approval opens a confirmation dialog with the exact action and retrieves a fresh request record first. No action executes until the operator confirms. The dashboard uses the bounded request and audit summary endpoints for polling and fetches full records when an operator opens details. Active and pending requests remain in the active queue while recent history is paged separately.

## Verification

The UI readiness suite starts a real local gateway with an isolated temporary workspace and state directory. It uses real request submission, approval, and filesystem execution. Tokens are read from that temporary state directory and are never printed in test output. The 200% check uses a 160 CSS-pixel viewport as the effective layout width of a 320 CSS-pixel viewport at 200% zoom; it does not claim to control browser chrome zoom.

```sh
npm run check
npx playwright test tests/ui-readiness.spec.ts
```

Verified: the strict TypeScript checks pass, and the Playwright readiness suite passes all **7 tests** against the local gateway. Axe reports no WCAG 2.1 A/AA violations in the tested light, dark, and approval-dialog screens. The suite verifies onboarding skip/replay persistence, rejected-token recovery and session-only storage, 320px and 160px layout widths, theme persistence, lazy request and audit detail reads, disabled/loading approval state, keyboard focus containment/restoration, and real file writes only after confirmation. It also checks that a new file does not exist before approval.

The UI production bundle was rebuilt with `npx vite build` after the last source change. Formatting and whitespace checks pass for the changed UI and test files.
